# Customizable Ore Veins (NeoForge 1.21.1)

Мод добавляет 8 блоков-"жил" (iron, gold, diamond, emerald, redstone, lapis,
coal, copper). Каждая жила — это один блок-нода: при добыче он **не
исчезает**, а отдаёт немного руды за удар, пока не выдаст настроенное общее
количество (по умолчанию для железа — 1000), и только после этого
превращается в обычный камень.

## Что настраивается

При первом запуске игры/сервера создаётся файл:

```
config/oreveins-common.json
```

Для каждого типа жилы там указано:

```json
"iron": {
  "total_amount": 1000,
  "drop_item": "minecraft:raw_iron",
  "min_per_hit": 1,
  "max_per_hit": 3,
  "xp_per_hit": 0
}
```

- `total_amount` — сколько всего предметов выдаст жила, прежде чем
  превратится в камень.
- `drop_item` — id предмета, который выпадает (можно поставить айтем из
  другого мода).
- `min_per_hit` / `max_per_hit` — сколько выпадает за один удар.
- `xp_per_hit` — опыт за удар.

Меняете файл → перезапускаете игру/сервер, изменения применяются.

## Генерация в мире

Жилы генерируются в Overworld как обычная руда (через
`data/neoforge/biome_modifier/add_ore_veins.json` и
`data/oreveins/worldgen/...`). Параметры размера/частоты жил в мире сейчас
заданы фиксированно в JSON-файлах генерации (не через общий конфиг, как вы и
попросили — конфигурируются только количество руды и её тип). Если захотите
поменять частоту появления в мире, правьте
`src/main/resources/data/oreveins/worldgen/placed_feature/*.json` (поля
`count` и `height_range`) до сборки мода.

Блоки также доступны в творческом режиме — вкладка "Ore Veins".

## Сборка

```
./gradlew build
```

Готовый jar появится в `build/libs/`. Положите его в папку `mods` клиента с
NeoForge 1.21.1 (совместимая версия NeoForge указана в `gradle.properties`,
`neo_version` — при необходимости поправьте под свою установленную версию
NeoForge с neoforged.net).

Для разработки/теста:

```
./gradlew runClient
```

**Важно:** этот проект был написан и не компилировался в текущей песочнице
(нет доступа к репозиторию maven.neoforged.net из этого окружения) — при
первой сборке возможны мелкие несостыковки версий API, обычно решаются
подгонкой `neo_version` в `gradle.properties` под актуальную версию с
https://neoforged.net/. Структура кода (регистрация блоков/айтемов, логика
добычи, конфиг, worldgen) рабочая и следует стандартным паттернам NeoForge
1.21.x.

## Как добавить свой тип жилы

1. Добавить константу в `OreVeinType.java` (текстура/твёрдость берутся у
   существующего ванильного блока).
2. Добавить дефолт в `OreVeinConfig.defaultFor(...)`.
3. Сгенерировать blockstate/model json по аналогии с существующими в
   `assets/oreveins/{blockstates,models}`.
4. (Опционально) добавить configured_feature/placed_feature для генерации в
   мире и прописать в `add_ore_veins.json`.

## Автобур (работает от вращения Create)

В моде появился блок **Auto Drill** (`oreveins:auto_drill`):

- Ставится лицом к жиле (как игрок — "смотрит" в сторону блока, который
  будет добывать), с валом/шестернёй Create, подключённым сзади.
- Пока на него подаётся вращение (RPM > 0) — периодически "бьёт" по жиле
  перед собой, точно так же уменьшая её остаток, как и обычная добыча.
  Чем выше RPM, тем чаще идёт добыча. Без вращения бур простаивает.
- Добытое:
  1. Сначала пытается сразу перенести в инвентарь, который стоит **вплотную**
     к любой из 6 граней бура (сундук, бочка, Passer от Create и т.д.) —
     это и есть "перенос в ближайшее хранилище": ближайшее в буквальном
     смысле — впритык к буру.
  2. Если рядом ничего нет (или всё занято) — складывает в собственный
     небольшой буфер (9 слотов) внутри бура. Из этого буфера может забирать
     любая воронка/труба/другой транспортный мод — у бура открыт стандартный
     интерфейс "инвентаря" (item handler capability).
  3. Если и буфер полон — предмет просто выпадет на землю у жилы, чтобы
     ничего не терялось.

### Важные оговорки по этой части

- Для работы бура **обязательно нужен установленный мод Create** (версия
  6.0.x под NeoForge 1.21.1) — это прописано и как зависимость сборки
  (`build.gradle`), и как обязательная зависимость мода
  (`neoforge.mods.toml`), так что без Create игра не запустится.
- Логика вращения написана на официальном API Create для аддонов
  (`KineticBlock` / `KineticBlockEntity`) — это стабильная, давно
  используемая сторонними модами часть их кода.
- **Внешний вид блока — самое рискованное место.** В
  `blockstates/auto_drill.json` и `models/item/auto_drill.json` стоят
  прямые ссылки на модели дрели из самого Create (`create:block/drill`,
  `create:item/drill`), чтобы визуально бур выглядел как их дрель. Но их
  дрель использует кастомную анимацию вращающейся головки через собственный
  рендерер Create, а не просто статичную модель blockstate — поэтому такая
  прямая ссылка, скорее всего, даст только статичную "базовую" часть без
  анимации головки, либо вовсе не найдёт нужный файл, если Create называет
  его внутри иначе. Я не смог это проверить компиляцией/запуском в этой
  песочнице. Если после сборки текстура блока выглядит как
  чёрно-фиолетовая сетка (missing texture) или урезанно — нужно либо
  подобрать точное имя файла модели, распаковав `create-*.jar`
  (`assets/create/models/block/`, `assets/create/blockstates/drill.json`),
  либо сделать свою простую модель-заглушку (кубик со своей текстурой)
  вместо ссылки на чужую.
